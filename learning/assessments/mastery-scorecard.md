# PHP Mastery Assessment Scorecard

This scorecard helps reviewers apply EMW consistently. It does not create an overall percentage-based PHP grade.

## Evidence dimensions

| Dimension | What to observe |
|---|---|
| Conceptual explanation | Can the developer describe the problem, semantics, and trade-offs accurately? |
| Prediction and tracing | Can they predict outputs or trace data/control flow before execution? |
| Implementation | Can they construct a working solution independently? |
| Debugging | Can they isolate root cause and create a regression check? |
| Testing | Can they identify meaningful edge cases and verify behavior? |
| Transfer | Can they adapt the concept to a novel requirement or domain? |
| Calibration | Does their confidence match observed performance? |

## Level guidance
- **M0 — Unknown:** no reliable evidence reviewed.
- **M1 — Awareness:** recognizes the concept and explains its basic purpose.
- **M2 — Guided Application:** successfully applies the concept with examples, hints, or AI assistance.
- **M3 — Independent Application:** independently implements, explains, tests, and debugs a representative task.
- **M4 — Transfer & Mastery:** independently transfers to unfamiliar cases, evaluates alternatives, explains limitations, and can teach the concept.

## Evidence conditions
Record:
- Exact task and date.
- PHP version and environment.
- Assistance A0–A4.
- What the developer did before receiving help.
- Tests/checks run and observed results.
- Whether the task was familiar or novel.
- Any relevant time or external constraints.
- Reviewer confidence and limitations.

A passing test is evidence about code behavior, not proof that the learner understands the code. A verbal explanation alone is rarely sufficient for M3. M4 requires transfer evidence.

## Review outcome
For each skill, recommend one action:
- Promote with evidence.
- Keep current level.
- Gather better evidence.
- Revisit prerequisite.
- Create a transfer exercise.
