# EMW Prompt 10 — Shared Knowledge Contribution

Use when project knowledge appears useful beyond its originating project.

This prompt prepares a contribution proposal. It does not authorize automatic publication.

1. Read the project entry and its evidence.
2. Explain why the lesson generalizes beyond this project.
3. Remove proprietary details, customer information, personal data, credentials, private source code, internal URLs, and environment secrets.
4. Generalize names, architecture, and examples while preserving the engineering lesson.
5. Verify references and avoid copying large portions of third-party documentation.
6. Check the shared EMW index for duplicates and conflicts.
7. Create a contribution using `.emw/templates/knowledge-contribution.md`.
8. Include evidence, applicability, versions, limitations, confidence, and proposed category.
9. Ask a human to review and approve publication.
10. Only after approval, add the shared entry and update `.emw/knowledge/index.yaml` through the repository's normal review process.

A project knowledge entry must never be copied wholesale into the shared base simply because it is useful. Privacy, security, licensing, generalizability, and correctness come first.
