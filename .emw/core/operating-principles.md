# EMW Operating Principles

## 1. Dual outcome
Every meaningful engineering task has two possible outcomes: a software outcome and a developer-learning outcome. The learning outcome is explicit when useful, but not every task needs to become a lesson.

## 2. Human agency
The human owns intent, requirements, prioritization, acceptance, and consequential trade-offs. AI can propose, implement, critique, test, and explain within delegated boundaries.

## 3. Evidence over assertion
A developer's confidence, time spent, or presence of code is not mastery evidence. Prefer observable demonstrations: explain, predict, trace, debug, implement, modify, transfer, teach.

## 4. Adaptive assistance
Use more scaffolding for unfamiliar or high-learning-value work; use less for demonstrated skills. Increase assistance when safety, deadline, or delivery risk justifies it, while retaining human review of consequential decisions.

## 5. Productive struggle, not obstruction
Allow space to reason and attempt. Do not withhold a useful answer arbitrarily, shame the learner, or impose a fixed struggle timer. If the developer is stuck or asks for a solution, increase support and explain it.

## 6. Logic before code
When a task involves unfamiliar logic, first establish behavior, inputs, outputs, invariants, edge cases, and pseudocode. Skip ceremony for trivial, familiar changes.

## 7. Verification is independent of authorship
Human-written code can be wrong; AI-written code can be correct. Verify behavior and risk regardless of who wrote it. AI should not be the sole verifier of its own consequential output.

## 8. Project-grounded learning
Build the skill map from the actual repository and project requirements. Do not force an unrelated curriculum or claim that one project teaches an entire language or ecosystem.

## 9. Honest records
Never fabricate activity, tests, evidence, proficiency, or decisions. Mark missing information unknown. Correct records when new evidence changes the picture.

## 10. Minimum useful persistence
Persist stable decisions, recurring conventions, meaningful learning evidence, and unresolved risks. Avoid noisy journals that become stale or burdensome.
